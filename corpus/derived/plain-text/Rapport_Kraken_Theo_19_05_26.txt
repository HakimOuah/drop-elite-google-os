⚔ DÉCRYPTAGE — LE SYSTÈME DE PIERRE
► NocoDB, le tableur qui remplace Airtable
Pierre a migré d’Airtable vers NocoDB, un tableur dynamique open source qu’il auto-héberge sur son VPS
(version gratuite, sans limite de colonnes). Pour lui, une ligne = un produit. Trois avantages concrets par rapport
à Google Sheets : plusieurs images dans une même cellule, des feuilles reliées entre projets (SAV, sourcing…),
et un chargement nettement plus rapide qu’Airtable qui laguait quand il poussait le volume.
Côté ressources, c’est léger : environ 1 % de CPU et 2 Go de RAM mobilisés. De quoi tourner sans souci,
même sur un petit serveur. Le coach a relancé l’idée de l’héberger sur un Raspberry Pi à domicile, par goût du
self-host (« l’appareil que je gère moi-même, que je peux customiser »), mais a conclu que pour Pierre, déjà
équipé d’un VPS, ça n’a pas d’intérêt.
Le bénéfice de fond : tes données t’appartiennent, tout est chez toi, et l’outil est open source.

► Le scraping : NPM dédié vs scraper universel
Emeric utilise un package NPM spécifique à AliExpress, appelé depuis un script Python via subprocess : le
module scrape la page, renvoie du JSON, et Python le retraite. Sa limite est structurelle — si AliExpress change
son HTML, le package casse tant qu’il n’est pas mis à jour.
Pierre, lui, teste un scraper universel trouvé sur GitHub (54 étoiles, gratuit, avec Claude parmi les
contributeurs). Il fonctionne sur n’importe quel site, contourne les protections antibot type Cloudflare, et affiche
des benchmarks très rapides. Lui ne vise que AliExpress et 1688. Son installation passe par Python (pip), donc
Claude peut le lancer et le piloter directement.

Pourquoi ce mélange Python / JavaScript ? Manuel l’explique clairement : une page web n’est que HTML,
CSS et JavaScript. Le scraping consiste à interroger le DOM (Document Object Model), ce que JavaScript fait
nativement et pas Python. Le choix de Python en orchestrateur est historique chez Emeric (cohérence avec ses

► Le pipeline d’intégration produit (démo live)
Le cœur du partage : un système construit sur environ un an, découpé en workflows déclenchés par des
webhooks (un bouton = un workflow) pour garder le contrôle à chaque étape.
1. Scraping & fusion. Le workflow scrape AliExpress et 1688, combine les deux (l’un complète l’autre), passe
les images en OCR via Replicate (moins d’un centime l’image) pour récupérer le texte incrusté, puis nettoie la
donnée avec Gemini pour ne garder que l’essentiel. Résultat : un JSON complet, ce que Pierre appelle sa
donnée first party.
2. Remplissage du tableau. Gemini, avec un output JSON structuré, répartit automatiquement les données
colonne par colonne : poids, tailles, litrage, nombre de poches, waterproof, catégories principale et secondaire.
3. Images. Téléchargées (préférence 1688, qualité supérieure), rangées dans Google Drive avec une
nomenclature par produit. Un workflow dédié enlève le fond (Replicate), ajoute une ombre (Nano Banana 2),
upscale, redimensionne en 1200x1200, compresse et range dans le dossier final.
4. Nom produit & mots-clés. Le titre est généré à partir de la donnée first party (rien n’est inventé) en piochant
dans une base statique de mots-clés long-tail issus de Semrush — marques exclues, intention transactionnelle
uniquement, triés une fois pour toutes lors de la recherche de niche.
5. Intégration finale. Le plus gros workflow analyse en temps réel les ID de catégories de la boutique, détecte
la catégorie adaptée, génère la fiche SEO (8000 caractères, une cinquantaine de métafields) plus une
description Merchant Center reformulée, distingue produit simple ou variable, et envoie le tout vers
WooCommerce (ou Shopify, en changeant juste les modules d’entrée/sortie). Un calcul de marge par produit,
alimenté par le prix d’achat scrappé, est intégré directement — sur le modèle du tableau partagé par Stéphanie.
Le coach a salué un travail « clean et entier », en insistant sur la valeur des détails accumulés. Pierre, lui,
recentre sur ce qui compte vraiment.
« Le plus important, c’est vraiment la donnée que tu prends en entrée. Si tu prends le contexte que
tu as déjà scrappé, tu auras une qualité de rédaction qui n’a rien à voir. »
— Pierre
⚙ PRINCIPES TRANSVERSAUX & RAPPELS
Au-delà de la démo, plusieurs enseignements valables pour tout le monde sont ressortis des échanges.
NPM et NPX, démystifiés (Manuel) — NPM (Node Package Manager) est l’environnement qui exécute le
JavaScript à partir des modules déclarés dans le fichier package.json ; c’est lui qu’on utilise en phase de
développement et de débogage. NPX exécute un paquet déjà installé sous forme de binaire — plutôt pour la
mise en production, plus rapide. Côté Python, l’équivalent est pip install / pip update.
Garder ses packages à jour — bonne pratique : commencer par un npm update avant d’installer. Astuce
concrète : mettre latest dans le package.json plutôt qu’un numéro de version fige, pour rester toujours à jour. Un
point à vérifier dans ses skills Claude — sachant qu’Emeric a constaté que sa skill de scraping était en Python,

Sécurité des comptes — la digression sur le hack Discord de Pierre (via un logiciel cracké) a rappelé le
mécanisme des cookies de session : ils évitent de se reconnecter en permanence, mais quiconque les récupère

« Si je récupère les cookies de ta page, je me fais passer pour toi sur le serveur et je récupère tes
informations. »
— Manuel
D’où les recommandations : ne jamais réutiliser le même mot de passe, utiliser un générateur, et passer par un
gestionnaire comme Proton Pass (gratuit, ou environ 2-3 €/mois pour les alias e-mail dynamiques qui isolent
ton vrai mail du spam et des fuites).
Lancer plutôt que fignoler — le fil rouge de la fin de session. Le coach a poussé Pierre (et Mika) à ne pas
perdre de temps à migrer un système qui fonctionne déjà (Airtable vers NocoDB, N8N vers Claude). Ces
refontes sont à garder pour le prochain site.
« Ton objectif, ça sera vraiment de lancer et pas de fignoler. Et après, tu fignoleras. »
— Théo
Emeric a complété par une mise en garde pour les débutants : le système de Pierre est un aboutissement, pas
