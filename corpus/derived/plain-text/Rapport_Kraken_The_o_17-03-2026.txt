► Connexion Shopify via MCP
Principe : Shopify propose un MCP (Model Context Protocol) permettant à Claude d’accéder directement au
site. La procédure : créer une application développeur dans Shopify, lui attribuer les droits nécessaires
(produits, metafields, menus...), récupérer le token d’accès, et le fournir à Claude.
Conseil : envoyer à Claude la documentation Shopify (fichier MD téléchargeable depuis les pages doc
officielles) pour qu’il comprenne l’installation. Shopify et d’autres outils proposent désormais des fichiers MD
spéciaux pour les IA dans leurs docs.
► Import produits : deux stratégies
Stratégie 1 — Sélection manuelle via DSers : sélectionner les produits sur AliExpress, importer via DSers sur
Shopify (titre anglais + images brutes + specs). Claude travaille ensuite à partir de ces données pour remplir et
optimiser chaque fiche. Recommandé pour garder le contrôle qualité sur la sélection.
Stratégie 2 — Automatisation via RapidAPI : utiliser une API AliExpress (via RapidAPI) pour rechercher par
mots-clés, récupérer 20 produits par requête, filtrer automatiquement via Claude, puis extraire les détails
(specs, images, prix) via l’endpoint détails produit avec l’ID. Résultat : un CSV local complet avec toutes les
données nécessaires.

► Création automatisée des fiches produits
Une fois les produits importés (titre anglais, images brutes, specs), Claude prend le relais pour composer la
fiche complète. Le coach a détaillé chaque bloc :
Description : rédigée à partir du titre, de 3 images analysées par Claude et des specs. Optimisée SEO,
originale, avec liste d’avantages.
Métafields : champs personnalisés Shopify (specs techniques, caractéristiques). Claude remplit à partir des
données récupérées. Pour WooCommerce : champs méta via plugin.

► Traitement des images par IA
Le coach a présenté un système de vérification et de génération d’images piloté par Claude. L’IA analyse
chaque image produit et applique des règles :
Détection : repérage du texte anglais incrusté, images de mauvaise qualité, montages AliExpress inappropriés.
Action : traduction du texte via génération d’image (NanoBanana), suppression ou remplacement des images
non conformes.
Principe : créer une liste d’instructions de vérification d’image spécifique à la niche. Faut définir ce qu’on veut,
ce qu’on veut pas, ce qui doit être traduit, ce qui doit être regénéré.
Résultat test : Théo a testé sur 3 produits. Claude a détecté les images avec texte anglais, généré la version
française via NanoBanana, et remplacé automatiquement. Fiche produit finale jugée clean.
« L’idée, c’est de faire une liste d’instruction de vérif d’image. Qu’est-ce qu’on veut, qu’est-ce qu’on
veut pas, qu’est-ce qu’on veut traduire, qu’est-ce qu’on veut refaire. »
— Coach Théo
► Optimisation automatique des performances
Claude a accès aux rapports Shopify via MCP. Le coach propose un workflow d’optimisation continue :
Détection : identifier les produits à faible taux de conversion (visites vs. ventes). Analyse : vérifier prix
(comparaison concurrents), images, cohérence description, specs manquantes. Action : tests automatiques
(ajustement prix, amélioration fiche) avec période d’observation (1 semaine) et récaps journaliers/hebdo.
Point clé : toujours intégrer un agent de vérification à la fin de chaque workflow. Théo utilise systématiquement
un sous-agent dédié au contrôle qualité qui vérifie le travail du skill principal.
« Dans tous mes workflows, il y a le dernier, c’est un agent qui vérifie. »
— Coach Théo

► Pierre — Process API, images & skills
Lien API/ID : la recherche API retourne un ID par produit. Cet ID est utilisé dans la deuxième requête (détails
produit) pour récupérer toutes les infos. Tout peut être stocké dans un CSV local (plus rapide et moins coûteux
qu’un Google Sheet).
Images : Pierre souhaite un contrôle en amont avant import Shopify. Solution : workflow Claude qui vérifie
chaque image, retire les non conformes, génère les manquantes, puis importe seulement les validées.
Skills : Théo recommande de créer ses propres skills plutôt que d’en télécharger. Un skill par tâche précise.
Pour les skills téléchargés : les lire soi-même d’abord, puis les faire vérifier par une autre IA (pas directement
par Claude pour éviter le prompt injection).
► Matthieu — Looker Studio & corrélation données
Matthieu utilise Looker Studio pour croiser les données WooCommerce et Google Ads. Problème : perte de
données dans Google Ads (produits avec 0 vente trackée mais 15 ventes réelles). Il filtre les ventes marquées «
Google Ads » non enregistrées + ventes marquées « direct » (considérées majoritairement comme du Google
Ads).
Réponse du coach : tout ce process de croisement de données peut être automatisé via Claude avec un
dashboard local + analyses automatiques. Plus besoin d’exports CSV manuels.
► Emeric — Agents vs. skills dans Cowork
Emeric (48h d’abonnement Claude) demande la différence entre agents et skills. Réponse : Théo ne crée pas
les agents manuellement. Il décrit le process complet et Claude crée automatiquement des sous-agents pour
chaque tâche. Dans OpenClaw, on peut créer des agents dédiés plus explicitement. Cowork = même moteur
que Claude Code, mais avec interface visuelle.
► Julien — Sécurité, normes DORA & failles CVE
Julien (profil sécurité informatique) a alerté sur plusieurs points :
Normes DORA : nouvelle réglementation européenne sur les plateformes financières. Des mises à jour de
checkout pourraient impacter les thèmes personnalisés. Nuance du coach : sur Shopify, le checkout est géré
par Shopify lui-même, donc le risque est limité.
Failles CVE : les agents IA (dont Claude Code) sont de plus en plus utilisés dans le piratage. Point de vigilance
pour les développements automatisés.
Plateformes : risque que les plateformes (AliExpress, etc.) bloquent les accès automatisés par agents IA à
terme (rate limiting, détection de bots).
